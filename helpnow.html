Building HelpNow SL: A Verified Home-Services Marketplace for Sri Lanka

AD
Aruna Darshana
Aug 8, 2026 · 10 min read ·

Every industry has that one everyday problem nobody's bothered to fix properly. In Sri Lanka, it's this: your tap starts leaking on a Sunday night, and the only way to find an electrician or plumber is to scroll through a neighbourhood WhatsApp group, ask around, and hope whoever shows up actually knows what they're doing. There's no way to check their track record, compare rates, or know if they'll turn up at all.

That gap is exactly what I set out to close with HelpNow SL — a full-stack, on-demand home-services marketplace connecting customers with verified electricians, plumbers, masons, carpenters, painters, AC technicians, and gardeners across the country. This post walks through what it does, how it's built, and what building a production-grade marketplace end-to-end actually looks like in practice.

"The goal was never just to list tradespeople online — it was to build trust into every step of the booking process."

The Problem With "Ask Around"

Hiring a tradesperson in Sri Lanka is almost entirely informal: word-of-mouth referrals, roadside signage, or community groups. That leaves customers with no reliable way to verify identity, qualifications, or past work quality, and no accountability if a job goes wrong. On the other side, skilled tradespeople with genuinely good work often have zero digital presence — they're invisible to anyone outside their immediate personal network, and they have no tools to track bookings, income, or customer communication in an organised way.

HelpNow SL addresses this by requiring every service provider to submit NIC front and back images, and optionally a police clearance report, during registration — all reviewed by an admin before the account goes live. From there, customers make decisions based on verified profiles, star ratings, and public comments, while providers get a proper digital storefront.

What's Actually Inside It

The platform is split into three connected experiences:

  • Customer side — browse service categories, view provider profiles with ratings and comments, book directly or broadcast a request to every nearby matching provider, track booking status, and rate completed jobs.
  • Partner side — a dashboard for managing bookings, earnings, and commission bills; listing multiple services under different categories; toggling live GPS sharing; posting 24-hour expiring status updates; and chatting with customers through a two-pane messaging inbox.
  • Admin side — a secured dashboard, protected by a standalone JWT + email OTP login, for approving providers, monitoring revenue, managing commission billing, and reviewing a full security log of every login attempt.

GPS-Based Discovery

One of the more interesting engineering problems was matching customers to nearby providers in real time. Both the Booking and ServiceProvider collections carry MongoDB 2dsphere geospatial indexes, which power two booking flows: a customer can book a specific provider directly, or fire off a "broadcast" request that pings every matching provider within range — whoever claims it first gets the job. It's a small feature on paper but it changes how quickly a customer can get help during an emergency.

Trust, Ratings, and Real Conversations

Every completed booking feeds into an automatic rating recalculation, so a provider's score is always a true reflection of recent work — not a static number set once at signup. Layered on top is a comment system with nested replies and emoji reactions (polymorphic, so both customers and providers can post), a WhatsApp-style 24-hour expiring status feature for providers to show recent work, and a two-pane, Messenger-style inbox for direct conversations.

Getting Paid, Properly

Because the platform runs on commission, billing had to be solid. Each provider gets one monthly invoice with an embedded ledger of payments, supporting both PayHere online payments and manual bank-transfer slip uploads. A Mongoose pre-save hook recalculates the amount paid and balance due automatically every time a payment lands — no manual reconciliation required.

Under the Hood

HelpNow SL runs on a three-tier, serverless architecture: a Next.js App Router front end, Next.js API routes deployed as serverless functions on Vercel, and MongoDB Atlas as the data layer, accessed through Mongoose. Authentication is split by role — Google OAuth for customers, credentials-based login with bcrypt hashing for partners — both via NextAuth v5, while the admin panel runs its own standalone JWT + OTP flow for extra separation.

Media (verification documents, certificates, profile photos, status content) is handled through Cloudinary, and Vercel Cron Jobs trigger scheduled functions for booking reminders and monthly billing notices, without needing a dedicated background server anywhere.

What Actually Went Wrong (And Got Fixed)

No production build ships without a few battle scars. A Turbopack bundling quirk broke the Billing schema's Mongoose pre-save hook by altering its parameter count, which took a while to trace back. GPS coordinates were silently dropped from booking requests because the front-end payload simply wasn't including them — a bug that only became obvious once nearby-search results started looking wrong. PayHere's sandbox also flatly rejects *.vercel.app preview domains, which meant payment testing needed an ngrok tunnel as a workaround. And a single admin page.js file quietly grew to about 4,200 lines before finally being refactored into proper utils, hooks, components, and views directories.

Why This Matters Beyond the Code

It's easy to treat a project like this as just a technical exercise — auth flows, geospatial queries, billing hooks. But the real preview it offers into the IT industry is everything that happens around the code: gathering requirements iteratively from real usage instead of a single upfront spec, shipping features one at a time to a live environment, debugging serverless quirks that only show up in production, and constantly trading off scope against time. That loop — build, deploy, observe, fix, repeat — is the actual day-to-day of software engineering, far more than any single framework or database choice.

HelpNow SL is still evolving — real-time messaging via WebSockets, an automated test suite, multi-admin roles, and Sinhala/Tamil language support are all on the roadmap. But it's already a working, end-to-end product that solves a real, everyday problem for real people.
